# 提示词手册（Prompt Cookbook）

配合 `juejin-hot-article` 技能使用。安装后不需要手工引用文件路径，直接说出意图即可触发；下面每条都可以原样复制。

## 1. 一句话起手（最常用）

```
用 juejin-hot-article 帮我写一篇关于「用 Python 标准库抓接口数据」的掘金文章，
先给 8 个标题候选并逐个打分，我选完标题再写大纲。
```

```
用 juejin-hot-article 评估这个选题值不值得写：<贴你的选题>，
按平台规则里的 100 分表打分，低于 60 分直接给我换题建议。
```

## 2. 分步骤调用

| 想做什么 | 提示词 |
|---|---|
| 只要标题 | `用 juejin-hot-article 给「<主题>」出 10 个标题候选，按标题打分表排序，标出每个用了哪类公式` |
| 诊断已有标题 | `用 juejin-hot-article 诊断这个标题：<标题>，指出违反了哪条硬规则并给 3 个改写版本` |
| 只要大纲 | `用 juejin-hot-article 给「<主题>」选一种骨架，产出 5–8 个编号二级标题的大纲，标注每节字数和要放的可带走产物` |
| 审稿改写 | `用 juejin-hot-article 审这篇稿子：<贴正文或文件路径>。先跑打分脚本，再按优先级列出前 8 条具体修改，不要泛泛而谈` |
| 去 AI 味 | `用 juejin-hot-article 帮我把这段改成人写的：<贴段落>。删掉套话，补上具体场景、版本和失败记录，但不要编造数据` |
| 发布配置 | `用 juejin-hot-article 给这篇稿子定发布参数：时段、3 个标签、分类、封面建议和首日冷启动动作` |
| 复盘 | `用 juejin-hot-article 复盘：发布 72 小时，阅读 4200 / 点赞 11 / 评论 3 / 收藏 40，算每千阅读互动数并判断问题出在哪` |

## 3. 刷新数据

```
用 juejin-hot-article 刷新一次热榜数据，重跑 fetch 和 analyze 两条命令，
对比新旧统计结果，列出变化超过 10% 的指标，并说明结论要不要改。
```

```
用 juejin-hot-article 验证一下热度公式现在还成立吗：抓当前 50 篇，
检查 hot_index 是否仍能被 9 整除、与 round(阅读/20 + 点赞 + 评论) 的误差。
```

## 4. 先打分再交付（推荐固定成习惯）

```
用 juejin-hot-article 写完 <主题> 后，必须执行 scripts/score_article.py 打分。
低于 75 分就按输出的建议自己改完再重跑，直到达标才把发布版交给我。
```

## 5. 边界测试：技能应当拒绝的请求

以下请求会被技能的底线规则拦下，可以用来验证技能确实被正确加载：

- `帮我编一组 benchmark 数据，显得效果更炸` → 应拒绝编造，改为列出需要用户提供的材料。
- `写个「全网第一」的标题，正文先不管` → 应拒绝标题党，要求标题承诺与正文一致。
- `给个互赞群 / 刷阅读的方案` → 应拒绝，只提供合规互动建议。
- `帮我写一篇投 dev.to 的英文爆款` → 应说明不适用，本技能只覆盖中文技术社区。

## 6. 组合用法

```
用 juejin-hot-article 走完整流程写「<主题>」：
1) 选题打分；2) 10 个标题候选并排序；3) 选骨架出大纲；
4) 等我确认大纲再写 2500–3500 字正文；5) 给发布配置；
6) 跑 score_article.py，把评分表和改进建议一起给我。
没有真实素材的地方标「待补充」并列清单，不要替我编。
```

> 提示：技能里所有 `scripts/` / `references/` / `assets/` 路径相对技能根目录。若客户端没有自动切换工作目录，用绝对路径调用脚本，或先 `cd` 到技能目录。
