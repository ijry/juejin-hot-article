# 掘金平台规则、评分表与发布 SOP

## 1. 榜单机制（2026-11-06 实测）

| 榜单 | URL | 窗口 | 排序依据 |
|---|---|---|---|
| 文章榜（综合） | `/hot/articles` | 最近 3 日 | 阅读 / 点赞 / 评论 / 收藏加权热度 |
| 文章榜（分类） | `/hot/articles/{category_id}` | 最近 7 日 | 同上，分类内排名 |
| 文章收藏榜 | `/hot/collected-articles` | 最近 3 个月 | 收藏数 |
| 优质作者榜 | `/hot/authors/{id}` | 周期 | 掘力值增量 |

官方接口（GET，无需登录）：

```
https://api.juejin.cn/content_api/v1/content/article_rank?category_id=1&type=hot
https://api.juejin.cn/content_api/v1/content/article_rank?category_id=1&type=collect
```

文章详情（POST，`aid` 与 `client_type` 必须是数字 2608，否则返回「参数错误」）：

```
POST https://api.juejin.cn/content_api/v1/article/detail
{"article_id":"...","aid":2608,"client_type":2608}
```

`category_id=1` 为综合；常用分类：后端 `6809637769959178254`、前端 `6809637767543259144`、人工智能 `6809637773935378440`、开发工具 `6809637771511070734`、代码人生 `6809637776263217160`、阅读 `6809637772874219534`、客户端 `6809635626879549454`。

### 热度公式（关键）

```
hot_index = 9 × round( 阅读/20 + 点赞 + 评论 )      收藏 ≈ 0 权重
```

50 篇样本中 48 篇误差 ≤1 分。换算：**1 个赞 ≈ 1 条评论 ≈ 20 次阅读**；收藏不进入文章榜，但对收藏榜有用。时间为硬窗口：综合榜只统计 3 日内发布（分类榜 7 日），过期不再累积。

战术含义：
- 别只盯阅读。结尾一个能回答的具体提问、评论区认真回复，比多求 200 次曝光更有效。
- 想要收藏榜，就把「速查表 / 配置模板 / 清单 / 工具书」放在正文前 1/3。
- 第 4 天起不再有热度累积，冲榜动作必须集中在 T0–T+72h。

## 2. 分类竞争度（7 日分类榜，同类可比）

| 分类 | 榜首热度 | 中位热度 | 进入门槛(末位) | 中位阅读 | 竞争判断 |
|---|---:|---:|---:|---:|---|
| 人工智能 | 13572 | 301.5 | 171 | 535 | 最卷，但流量最大 |
| 前端 | 13212 | 292.5 | 207 | 517 | 最卷，门槛最高 |
| 客户端 | 747 | 207 | 99 | 408 | 中等 |
| 后端 | 7560 | 189 | 99 | 361.5 | 中等 |
| 开发工具 | 4446 | 144 | 90 | 286.5 | 较容易 |
| 代码人生 | 1548 | 108 | 63 | 219 | 容易 |
| 阅读 | 1053 | 54 | 18 | 113 | 最容易，但流量最小 |

用法：新人或冷启动账号优先从「开发工具 / 后端 / 客户端」切入；有存量读者的账号再冲 AI / 前端。不要把技术文章硬塞进「阅读」等低竞争分类来刷榜——分类与标签错配会损伤推荐精准度。

## 3. 选题评分表（100 分，<60 换题）

| 维度 | 分值 | 打分依据 |
|---|---:|---|
| 热点绑定 | 20 | 与当期热词真实相关 20；能蹭但需绕弯 10；无关 0 |
| 痛点强度 | 20 | 读者今天就会遇到 20；偶尔遇到 10；纯好奇 5 |
| 可验证素材 | 25 | 有本人实测/数据/失败记录 25；只有官方文档 10；只有观点 0 |
| 可带走产物 | 20 | 代码/配置/清单/速查表 20；思路 10；无 0 |
| 受众与竞争 | 15 | 受众大且分类门槛适中 15；受众大但极卷 8；小众 5 |

额外加分（最多 +10，总分封顶 100）：有反常识结论 +5；可做系列但有单篇完整性 +5。
一票否决：需要编造数据才能成立；标题承诺正文无法兑现；纯搬运无增量。

## 4. 发布配置清单

| 项 | 建议 | 依据 |
|---|---|---|
| 时段 | 工作日 08:00–10:00（首选 09:00 左右）；次选 20:00–21:00 | 50 篇样本 48% 在 08–10 点发布 |
| 标签 | 恰好 3 个：1 大分类 + 1 技术栈 + 1 热点词 | 两榜中位都是 3 个，上限 3 |
| 分类 | 按内容真实归属选；冷启动可选门槛较低分类 | 见竞争度表 |
| 封面 | 配 1 张与标题强相关的图 | 62% 上榜文章有封面 |
| 原创 | 声明原创，标注首发 | 平台推荐与版权 |
| 正文规格 | 2500–3500 字、5–8 个编号章节、代码块 ≥1、图/表 ≥1 | 见 `article-templates.md` |
| 结尾 | 总结 + 一个具体提问 + 资源链接 | 仅 36% / 22% 的样本做了，是明显机会 |

## 5. 冷启动 SOP（只做合规动作）

| 时点 | 动作 |
|---|---|
| T−1 天 | 备好封面、3 个标签、仓库/演示链接；把标题候选发给 1–2 位同行看能否一眼说出收益 |
| T0 发布 | 09:00 左右发布；确认 Markdown 渲染、代码块语言高亮、图片可见、链接可访问 |
| T+2h | 自己通读一遍，修正错别字与失效链接；在评论区补一条「延伸问题 / 勘误 / 补充资料」 |
| T+24h | 认真回复前 10 条评论（具体技术回答，不刷「感谢支持」）；把高频追问补进正文并注明更新 |
| T+48–72h | 记录阅读/点赞/评论/收藏，计算每千阅读互动数；判断是否值得写成系列第 2 篇 |
| T+72h | 热度窗口关闭，转为长尾：完善速查表、补 FAQ、把文章收进专栏/合集 |

**禁止**：互赞群、买阅读、刷评论、小号点赞、标题与内容错配骗点击、把同一篇改标题重复发。

## 6. 避坑清单

1. **高阅读零互动 = 噪声，不是模板**。识别阈值：每千阅读互动 < 5。本次 3 日榜前 3 名阅读 9.5k–16k，赞仅 2–5，互动率 0.4–1.3/1000；中位文章是 20.7/1000。不要模仿它们的标题与选题。
2. **「术语：副标题」长标题是短榜特征**。3 日榜 38% 用冒号，收藏榜仅 13.3%；长尾标题中位 23 字。
3. **纯快讯寿命 < 72h**。「XX 发布了 / 崩了 / 来了」若无独家增量，窗口过后归零。
4. **热词堆砌**。70% 的上榜标题含热词，但堆 3 个以上会稀释信息；绑 1 个即可。
5. **标签错配**。样本中大量 AI 文章挂「后端」标签，属于分发噪声；按真实内容配 3 个标签更利于长期推荐。
6. **AI 味 / 空泛结论**。用具体数字、失败记录、边界说明替代「显著提升」「综上所述」。
7. **只求收藏**。文章榜热度里收藏几乎不计分，冲榜要设计讨论点；收藏榜要设计可存档产物。
8. **忽略时间窗**。发布 3 天后再推广，对文章榜已无帮助。

## 7. 复盘指标

| 指标 | 计算 | 参考值 |
|---|---|---|
| 每千阅读互动 | (赞+评+藏)/阅读×1000 | 3 日榜中位 20.7；收藏榜中位 34.2；<10 说明内容匹配度有问题 |
| 收藏率 | 收藏/阅读 | 长尾型内容应显著高于 1% |
| 评论率 | 评论/阅读 | 争议/疑问型标题应高于 0.3% |
| 热度当量 | 阅读/20 + 赞 + 评 | 对照当周分类榜末位门槛判断是否上榜 |
| 长尾比 | T+30 天阅读 / T+3 天阅读 | >2 说明选题有长期价值，可做系列 |

## 8. 数据刷新

规律会随平台调整与热点周期变化，建议每月或大版本热点出现时刷新一次：

```bash
python scripts/fetch_juejin.py --out ./data --limit 50
python scripts/analyze_juejin.py --data ./data --out ./analysis
```

重点看三处是否变化：`stats.json` 的 `heat_model.coefficients`（公式是否调整）、`feature_deltas`（标题战术迁移）、`category_boards.entry_heat`（分类门槛）。
