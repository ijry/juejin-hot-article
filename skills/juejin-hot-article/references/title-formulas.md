# 掘金标题公式库

案例全部来自 2026-11-06 抓取的真实榜单（标注 `[3日]` = 文章榜、`[收藏]` = 文章收藏榜）。公式用于生成候选，不是套壳生产标题；每个候选必须能用正文兑现。

## 一、10 类高命中公式

### 1. 数字清单 + 亲测筛选〔最利于收藏〕

模板：`N 个/款/步 X，我全试了，只有 M 个能用` / `N 个 X，亲测好用`
- `[3日]` Skills 榜前 10 我全装了：只有 3 个能直接用
- `[3日]` GitHub 上最值得装的 8 个 Agent Skill 仓库，亲测好用！
- `[收藏]` DeepSeek Harness 值得安装的 15 款插件
- 适用：工具/插件/资源/配置项评测。必须有真实筛选标准与淘汰理由，不能只是罗列。

### 2. 反常识质疑〔最利于评论〕

模板：`被吹上天的 X，为什么 Y 一个都不用` / `X 到底在保护谁？` / `别再 X 了`
- `[收藏]` 被吹上天的 JWT，为什么主流网站一个都不用
- `[3日]` CORS 到底在保护谁？90% 的前端理解错了跨域的本质
- `[收藏]` 别让 Codex 一口气写完整个前端：5 组 Skills，把页面、逻辑、测试和构建拆清楚
- 适用：有明确错误认知可纠正的话题。正文必须给出证据和适用边界，否则就是抬杠。

### 3. 实测时长 / 数据量〔最利于可信度〕

模板：`我 X 了 N 小时/ N 个 / N 次，结果是…`
- `[收藏]` 手机到底有没有偷听我们？我抓包了 72 小时，抓到了真凶
- `[收藏]` 2026年金九银十，我面了22个前端
- `[3日]` 一个人，4个岗位，20天：我用Cursor+Codex上线了一款微信小游戏（收藏榜同类）
- 适用：真的做过、有过程记录。数字必须真实。

### 4. 数字对比 / 收益前置〔最利于点击〕

模板：`A 干掉 B 行代码` / `N 秒完成 M 个 X` / `不花一分钱做到 Y`
- `[收藏]` 一行 CSS 新特性干掉 20 行 JavaScript ?
- `[收藏]` 前端2秒生成500页矢量PDF，rust真的强到没朋友
- `[3日]` 不花一分额外 API 钱，用现成的 Claude Code / Codex / Cursor 额度
- 适用：性能、成本、效率类可量化结论。必须写清测试环境与复现方式。

### 5. 踩坑复盘〔最利于共鸣〕

模板：`做了个 X，我把 N 个坑踩了一遍` / `X 实战，踩过的 N 个坑`
- `[3日]` 做了个匿名聊天站，我把 7 个前端坑踩了一遍
- `[3日]` iPhone Duo 适配实战，Awaking 踩过的 8 个坑
- 适用：真实项目。每坑按「现象 → 原因 → 修复 → 可复用检查项」写。

### 6. 第一人称造物〔最利于关注转化〕

模板：`我用 X 做了个 Y，然后把它开源/上线了`
- `[3日]` 我用 AI 给自己写了一个 Markdown 编辑器，然后把它开源了
- `[收藏]` 甲方只给了一张卫星截图，我用 Three.js + Blender 建了一座 3D 能源站
- `[3日]` 用 Codex 魔改卡神开源的 AIHOT，我做了个 3D 技术雷达
- 适用：有可展示成品。正文必须有仓库/演示链接与实现关键决策。

### 7. 疑问 / 争议〔最利于评论〕

模板：`X 是骗局还是出路？` / `X 真的会 Y 吗？` / `为什么 X 之后，Y 还没变？`
- `[收藏]` 做全栈是前端骗局还是出路？
- `[收藏]` AI会让程序员失业吗？200年前的手工织工已经给出了答案
- `[3日]` AI 会写代码之后，交付为什么还没变快？
- 适用：行业议题。必须给出自己的判断与理由，不能两边各打五十大板后收尾。

### 8. 时效新闻 + 独家增量〔只适合冲 3 日榜〕

模板：`X 昨晚刚 Y：附 N 万字实操/亲测/踩坑`
- `[收藏]` DeepSeek 昨晚刚开源了 Harness：附万少的2 万字保姆级教程
- `[3日]` 腾讯混元 Hy4 正式版发布了
- 风险提示：纯快讯生命周期不足 72 小时，且极易沦为无增量搬运。**只有在能提供官方没有的实测、源码解读或教程时才用**。

### 9. 方案 / 规范直给〔最利于长尾收藏〕

模板：`支持 X 的 Y 方案` / `一线大厂的 X 规范` / `N 张图吃透 X`
- `[收藏]` 支持独立部署的地图方案
- `[收藏]` 一线大厂的Git规范
- `[收藏]` 9 张 AI 生成的图，吃透任何一个前端项目
- 适用：工具书型内容。标题越朴素越好，价值靠正文密度。

### 10. 参数直给 / 极简具体

模板：`场景, 参数, 技术栈, 结果`
- `[收藏]` 网页端, 6.5MB人脸识别模型, 谷歌框架, 又快又准
- `[收藏]` 高级前端开发职业规划（2026—2035）
- `[收藏]` 前端 AI 面试题
- 适用：搜索流量型内容。中位标题长度最短（23 字）的收藏榜里，这类占比很高。

## 二、标题打分表（满分 100，≥80 才可交付）

| 项 | 分值 | 判定 |
|---|---:|---|
| 长度 18–28 字 | 15 | 18–28 满分；29–34 得 8；>34 或 <12 得 0 |
| 具体数字 / 具体对象 | 15 | 有阿拉伯数字或可验证的专名，且指向正文实据 |
| 钩子 | 20 | 反常识 / 疑问 / 第一人称实测 / 明确收益 / 时效，任一即可 |
| 承诺可兑现 | 15 | 正文确实给出该结果、清单或数据 |
| 热词绑定 | 10 | 恰好 1 个当期热词，且与内容真实相关 |
| 简洁度 | 10 | 无「术语：副标题」堆砌、无 3 个以上热词、无空泛修饰 |
| 可信度 | 10 | 有实测/数据/来源暗示（如「亲测」「抓包」「复盘」） |
| 无禁用词 | 5 | 不出现「全网第一」「震惊」「必看」「万字长文」（除非真写了）等 |

扣分项：出现 emoji 堆叠 −5；标题与分类/标签明显错配 −5；纯资讯无增量 −10。

## 三、反例（来自样本，标注问题）

| 标题 | 问题 |
|---|---|
| ValidX 正则表达式预编译优化：Pattern 复用策略 | 术语 + 冒号副标题、无钩子、无数字；该文 16k 阅读仅 3 赞（每千阅读互动 0.43），属高阅读零互动异常样本 |
| OpenTelemetry 生产实践：Skyscanner 24 集群管理经验与 Mastodon 小团队方案 | 68 字、三套术语并置、读者看不出收益 |

| 未来十年的建议 | 过泛，无对象、无场景、无钩子 |
| 🚀🚀【封闭结束8】Agent RAG：从零搭建一个可用知识库 | 表情 + 社群黑话 + 冒号，信息噪声大 |
| DeepSeek 再次崩了，DeepSeek V5正在路上？ | 纯猜测型快讯，无增量，72 小时后失效 |

## 四、生成流程

1. 从选题中抽出：**对象**（技术/工具）、**动作**（实测/排查/对比/搭建）、**结果**（数字/结论/产物）、**受众痛点**。
2. 选 3 类互不相同的公式，每类写 3 个候选 → 共 9 个。
3. 用打分表逐项打分，剔除 <70 分。
4. 前 3 名交给用户，并说明各自适合的赛道（冲榜 / 长尾 / 搜索）。
5. 最终标题必须再核对一次：正文里能指出兑现该标题的那一节。
