# 掘金高热文章创作与诊断

> 本文件遵循 [Agent Skills 规范](https://agentskills.io/specification)。下文所有 `scripts/`、`references/`、`assets/` 路径均相对技能根目录；执行脚本前先切换到该目录，或在命令中使用绝对路径。

## 目的

把「掘金上什么文章更容易热」变成一套可执行、可复用的生产流程：选对题 → 取好标题 → 搭对骨架 → 写足证据 → 配好发布参数 → 冷启动引导互动 → 发前自检打分。所有结论来自 2026-11-06 对掘金官方榜单接口抓取的 50 篇 3 日文章榜 + 30 篇 3 月收藏榜 + 7 个分类榜的量化分析，详见 `references/research-report.md`。

## 何时使用

- 用户要写 / 构思 / 改写一篇面向掘金（或同类中文技术社区）的文章。
- 用户要标题候选、选题评估、大纲、审稿、复盘、提升阅读或互动。
- 用户问「怎么上热榜」「什么时间发」「打什么标签」。
- 用户要求刷新热榜数据、重新验证规律。
- 不适用：纯代码调试、非中文社区（如 dev.to / Medium）的投放策略、需要编造数据或刷量的请求。

## 不可违背的底线

1. **不编造数据、案例、截图、benchmark、引用出处**。没有真实素材时，明确写「待补充」并列出需要用户提供的材料，不得代替用户虚构。
2. **不写标题党**：标题承诺必须在正文兑现；不用「全网第一」「震惊」「必看」等空夸大词。
3. **不引导刷量、互赞、买阅读**。热度公式虽可被利用，但只通过真实内容与合规互动提升。
4. **去 AI 味**：禁用「在当今…」「随着…的发展」「综上所述，本文…」「首先/其次/最后」三段式套话；用具体场景、具体数字、第一人称实测替代。
5. 技术结论必须可验证；涉及版本、API、命令时标注环境与版本，必要时联网核对。

## 核心工作流

### 第 0 步：确定目标赛道（必做，先问清或按默认推断）

| 目标 | 榜单口径 | 主攻指标 | 内容取向 |
|---|---|---|---|
| 冲 3 日文章榜 | 最近 3 日发布，按热度分排序 | 阅读 + 点赞 + 评论 | 热点绑定、快、密度高 |
| 冲 3 月文章收藏榜 | 最近 3 个月，按收藏数排序 | 收藏 | 清单、教程、可复用资料 |
| 长期品牌沉淀 | 无窗口 | 收藏率、评论质量、关注转化 | 深原理、体系化、系列化 |

默认采用「主攻 3 日文章榜，同时写成值得收藏的长尾内容」的双目标策略。

### 第 1 步：选题打分

用 `references/platform-rules.md` 的选题评分表对候选题打分（热点绑定 / 痛点强度 / 可验证素材 / 受众规模 / 竞争度，共 100 分）。**低于 60 分的选题换掉，不要靠标题补救。**
优先选择能同时满足以下三项的题：① 与当下热词真实相关（AI、Agent、DeepSeek、Codex、Skill、RAG、MCP、前端/后端新版本等）；② 有本人实测过程、失败记录或数据；③ 读者能立刻拿走一个可复用产物（代码、命令、清单、配置、避坑表）。

### 第 2 步：生成标题（≥8 个候选）

严格按 `references/title-formulas.md`：套用 10 类公式 → 生成候选 → 按标题打分表逐项打分 → 选前 3 个交给用户。硬规则：

- 长度 **18–28 字**最佳（3 日榜中位 32 字，但长尾高价值样本中位仅 23 字，短标题更耐看）。
- 必须含 **具体数字或具体对象**（如「72 小时」「8 个坑」「500 页 PDF」「22 个前端」）。
- 至少含一个钩子：反常识 / 疑问 / 第一人称实测 / 明确收益 / 时效。
- **避免**「术语堆砌 + 冒号 + 副标题」式长标题（3 日榜 38% 用冒号，收藏榜仅 13.3%）。
- 绑定 1 个热词即可，不堆 3 个以上。

### 第 3 步：选骨架并写大纲

从 `references/article-templates.md` 选一种骨架（实战复盘 / 踩坑排错 / 清单测评 / 原理深挖 / 观点争议），产出带二级标题编号的大纲。默认规格：

- 正文 **2500–3500 字**（两榜中位数分别 2500 / 3271 字），阅读时长 8–12 分钟。
- 5–8 个编号二级标题，每 300–500 字一节；长文加目录。
- 至少 1 段可运行代码/命令、1 张图或表格、1 组真实数据。
- 开头用「结论先行 / 提问 / 具体事故现场」之一（样本中 50% 提问开场、42% 背景铺垫）；结尾必须有总结 + 一个具体提问 + 资源链接（样本中 36% 互动引导、22% 资源链接，仍有明显提升空间）。

### 第 4 步：写正文

按 `references/article-templates.md` 的写作规范逐节填充。每一节都要有「可带走的东西」：结论、代码、配置、对照表或踩坑记录。禁止用大段概念解释充字数。事实、版本、链接逐条核对。

### 第 5 步：发布配置与冷启动

按 `references/platform-rules.md`：

- **时段**：优先工作日 **08:00–10:00**（50 篇样本中 48% 在这个窗口发布），次选 20:00–21:00。
- **标签**：恰好 3 个 = 1 个大分类 + 1 个技术栈 + 1 个热点词；分类选竞争度更低的入口（见分类榜门槛表）。
- **封面**：约 62% 上榜文章有封面，配一张与标题强相关的图。
- **原创**：声明原创，不搬运。
- **3 日窗口**：热度只在最近 3 日内有效，发布后 24–72 小时是唯一冲榜期；首日在评论区补一个「延伸问题/勘误/补充链接」并认真回复前 10 条评论。
- **引导点赞与评论**，不要只求收藏：文章榜热度分里 1 个赞 ≈ 1 条评论 ≈ 20 次阅读，收藏几乎不计入文章榜（但计入收藏榜）。

### 第 6 步：发前自检（必须执行）

```bash
python scripts/score_article.py path/to/draft.md
```

脚本输出 100 分制评分与逐项改进建议。**低于 75 分不得交付发布版**，按提示改完再跑一次。用户只要标题时，可用 `--title-only` 只做标题诊断。

### 第 7 步：复盘与刷新数据（可选）

文章发布 72 小时后，记录阅读/点赞/评论/收藏，计算每千阅读互动数（真实读者信号，3 日榜中位 ≈ 20.7，高价值样本 ≈ 34.2）；若互动率低于 10/1000，问题在内容匹配度而非曝光。

需要更新规律时：

```bash
python scripts/fetch_juejin.py --out ./data --limit 50
python scripts/analyze_juejin.py --data ./data --out ./analysis
```

## 一句话记住

**热榜 = 3 日内(阅读÷20 + 点赞 + 评论) 的相对排名；长尾 = 值得收藏的具体产物。**
所以：标题短而具体、内容有真实实测、结构可扫读、发在早上、三天内把互动做起来。
